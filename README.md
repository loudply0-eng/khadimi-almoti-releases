# خادمي المطيع — البناء والإصدارات

هذا المستودع **عام** ويستضيف بيئة GitHub Actions لبناء نسخة Windows من خادمي المطيع، ثم حفظ نواتج البناء القابلة للتنزيل.

## تقسيم المشروع

- المستودع الخاص `loudply0-eng/khadimi-almoti`: يحتفظ بالشيفرة المصدرية الأصلية وملفات التطوير.
- هذا المستودع العام: يحتوي Workflow البناء، وسجل البناء، وملفات الإصدارات التي نقرر نشرها.
- يقرأ Workflow المصدر الخاص باستخدام مفتاح Deploy Key بصلاحية قراءة فقط محفوظ في GitHub Actions Secret باسم `KHADIMI_SOURCE_READ_KEY`.

## تشغيل البناء

1. افتح تبويب **Actions**.
2. اختر **Khadimi Windows Build**.
3. اضغط **Run workflow**.
4. اختر فرع المصدر الخاص. اترك `project_path` فارغاً عندما يحتوي المصدر على ملف `.csproj` واحد فقط؛ وإلا حدّد مسار مشروع التطبيق الرئيسي نسبةً إلى جذر المصدر.
5. بعد نجاح البناء، نزّل ملف Windows ZIP وملف `SHA256SUMS.txt` من Artifacts في صفحة التشغيل.

## حدود النشر الحالية

- البناء اليدوي ينتج Artifact في GitHub Actions؛ لا ينشر إصداراً عاماً تلقائياً ولا ينشئ Release.
- لن ينجح البناء قبل وجود الشيفرة المصدرية الفعلية في المستودع الخاص وإعداد Secret القراءة فقط.
- يلزم التحقق من التطبيق الناتج قبل اعتماده كتحديث رسمي للمستخدمين.

## تنبيه أمني

- لا ترفع الشيفرة المصدرية الخاصة إلى هذا المستودع العام.
- لا تضع كلمات المرور أو رموز الوصول أو مفاتيح التوقيع الخاصة في Git.
- لا ترفع ملفات النماذج أو قواعد بيانات المستخدمين أو المحادثات أو بياناتهم.
- يُحفظ مفتاح الوصول إلى المصدر في GitHub Actions Secrets فقط، ويجب أن يبقى Deploy Key في المستودع الخاص للقراءة فقط.
- قيمة SHA-256 تكشف تلف الملف، لكنها ليست بديلاً عن التوقيع الرقمي للتحقق من هوية الناشر.
